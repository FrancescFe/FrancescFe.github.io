## Rejected or superseded alternatives

### Separate Projects page

The original architecture proposed a dedicated Projects List page at `/projects/`.

This was superseded by integrating project discovery directly into the Homepage.

The integrated approach reduces navigation depth and creates a more continuous portfolio experience.

### Separate project-detail pages

The original architecture proposed dedicated routes such as `/projects/numpairs/`.

The approved design instead places project details sequentially within the Homepage.

This allows visitors to move naturally from project discovery into case-study content while stable anchors preserve direct navigation to individual projects.

Dedicated project pages may be reconsidered in a future version if the number or complexity of projects makes the single-page model impractical.

### Privacy Policy in primary navigation

The Privacy Policy was deliberately excluded from the main navigation because it is a legal/product resource rather than a primary portfolio destination.

It remains available through its stable direct URL and relevant contextual links.

### Email link in the footer

An email link was considered but removed.

The footer is intentionally limited to GitHub and LinkedIn to keep the persistent navigation surface minimal.

### Light mode

A light theme was considered unnecessary for v1.

The dark theme is part of the portfolio's visual identity, so v1 does not include theme switching.

### Elaborate IDE simulation

The portfolio borrows visual cues from development tools but deliberately avoids reproducing a complete IDE or terminal interface.

The technical references should provide character without reducing usability or making the site feel like a novelty interface.
