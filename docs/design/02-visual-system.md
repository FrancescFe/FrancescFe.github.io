## Theme and color direction

The portfolio uses a **dark-only theme**.

No light theme or theme selector is planned for v1.

The approved visual direction uses:

- a dark charcoal/navy background;
- slightly lighter surfaces where separation is necessary;
- cool neutral colors for secondary text and borders;
- a teal/cyan accent for interactive elements, highlights, status indicators, and selected states.

The initial mockups use approximately:

- Background: `#0F172A`
- Accent: `#2DD4BF`

These values describe the approved visual direction rather than the final implementation tokens. The definitive palette, semantic color roles, interaction states, and contrast values will be formalized during Stage 2.

Color should remain restrained. The accent color is intended primarily to communicate hierarchy and interactivity rather than to decorate large areas of the interface.

## Typography

**JetBrains Mono** is the primary typeface across the portfolio.

Using a monospace typeface reinforces the technical identity and creates consistency between navigation, headings, metadata, project information, and long-form content.

The design must nevertheless prioritize readability over the developer aesthetic, particularly for:

- long project descriptions;
- the Resume;
- the Privacy Policy.

Stage 2 should validate the final font sizes, line heights, weights, measure, and responsive typography to ensure that the monospace choice remains comfortable for dense and long-form reading.

## Graphic language

The visual system uses restrained references to software development.

Candidate motifs include:

- terminal prompts;
- editor/file conventions;
- monospace labels;
- technical metadata;
- compact status indicators;
- code-like structural separators.

These references establish personality without turning the portfolio into a simulated terminal or IDE.

The primary content should always remain recognizable as a conventional website.

Complex decorative animation is intentionally avoided.
